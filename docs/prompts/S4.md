C2. Acting-as semantics (fixes chat meals not matching replayed glucose). Following replay participant p_xxx means the user acts as p_xxx. Replay withholds p_xxx's food-log meals. When one comes due, the backend pushes a StoryCard of type "meal_due" with the real meal text and a one-tap "Log it" action. If it isn't logged within 10 replay minutes, the backend logs it with source "replay_auto". Free-text chat meals for a followed replay participant that don't match the due meal become simulations, not logged meals, and the reply says so.
